## 1. 출처와 요청

서울 열린데이터광장의 [OA-21709 명세](https://data.seoul.go.kr/dataList/OA-21709/S/1/datasetView.do)와 실제 응답을 대조했다. 서비스명은 **`GetParkingInfo`**다. 포털의 Open API 탭 명세는 `POST https://data.seoul.go.kr/dataList/openApiView.do?infId=OA-21709&srvType=A`에서 확인했다. 선택 인자는 `ADDR`(자치구명)이며 공식 예시는 `/1/5/구로구`다. 이번에는 지역 필터 없이 서울 전체를 받았다.

```text
GET http://openapi.seoul.go.kr:8088/***/json/GetParkingInfo/1/1000/
```

인증키가 URL **경로**에 들어간다. 도구는 환경변수 `ROAD_AHEAD_SEOUL_KEY` 또는 루트 `api`의 `서울 api = '...'`를 읽고, 실제 URL은 curl 표준입력에만 전달한다. 저장 URL·본문·오류에서 키와 URL 인코딩 형태를 `***`로 지운다. 키가 들어간 명령행, 디버그 URL 로그, HTTP 요청 로거를 남기지 않는다.

정상 JSON은 `GetParkingInfo.list_total_count`, `GetParkingInfo.RESULT.CODE="INFO-000"`, `GetParkingInfo.row` 배열이다. 전체 **122행·고유 `PKLT_CD` 122개**, 행 필드는 **42개**다. 한 번의 `1/1000` 요청에 전부 들어왔다. 최대 1,000행은 공식 제한이며, 향후 총계가 커지면 `1001/2000`처럼 이어 받고 총계와 실제 길이를 검증해야 한다.

## 4. KOTSA 대응과 시청 주변

## 5. 다음 작업의 요청·파서 계약

1. 서울 전체 `1/1000` **1회**를 요청하고 같은 응답을 여러 후보가 공유한다. 현재 122행이라 약 130KB다. 자치구 필터는 공식 지원하지만 경계 주변을 누락할 수 있고 이번에는 실측하지 않았다. 현재 범위에서는 구별 여러 번 조회할 이유가 없다. `list_total_count`가 커지면 최대 1,000행씩 추가 조회한다. ID·좌표·반경 필터를 추측해 붙이지 않는다.
2. HTTP 상태, JSON/XML 여부, 본문 결과 코드를 모두 검사한다. 성공 배열과 무자료·실패를 구분한다. `PKLT_CD`를 문자열 키로 쓰고 같은 코드가 중복되면 면수·차량 수를 합산하지 않는다. 서로 충돌하면 해당 값은 보류한다.
3. 총면수=`TPKCT`, 점유=`NOW_PRK_VHCL_CNT`, **빈자리=총면수−점유**. 두 값이 유한 정수, 총면수>0, `0 ≤ 점유 ≤ 총면수`, `PRK_STTS_YN="1"`, 파싱 가능한 갱신 시각, **`0 ≤ 조회시각−갱신시각 ≤ 600초`**일 때만 빈자리 수를 만든다. 실패·미연계·미래시각·범위 오류·오래된 값은 null로 둔다. 음수 등을 0으로 잘라 정상 값처럼 보이지 않는다.
4. DESIGN §10의 **10분 기준은 유지할 수 있다**. 서버의 연계 표시는 20분 기준이므로 반드시 갱신 시각을 별도로 검사한다. 수신 후에도 캐시 값의 나이가 계속 증가해야 한다. 요청 시각만 새로워졌다고 생산 시각을 갱신하지 않는다. 한 저녁 실측 결과가 항상 10분 이내라는 보장은 아니다. 갱신 요청은 60초 간격을 후보로 제안하며 실제 앱 트리거·키별 일일 한도는 T-30 설계에서 결정한다.
5. 승용차 요금은 `BSC_PRK_CRG/BSC_PRK_HR`, `ADD_PRK_CRG/ADD_PRK_HR`를 쌍으로 쓴다. 동국제강은 서울 5분/700원, 기존 자산 30분/4,200원으로 기준 시간부터 다르다. 금액만 덮어쓰면 안 된다. 0·빈 값은 무료 구분 및 시간과 함께 검사하고, 일최대 0을 무료로 해석하지 않는다. 운영 시간·토요일·공휴일 요금도 구분한다.
6. 이름 정규화 78곳을 즉시 일괄 연결하지 않는다. 우선 확인한 소수의 명시적 ID 대응표로 시작하고, 주소·좌표를 확보한 뒤 50m 후보+이름+주소 검증을 늘린다. 서울 API에 없는 곳은 기존 자산의 이름·좌표·요금만 유지하며 실시간은 null이다. 이 측정은 새 자산 형식이나 앱 코드를 바꾸지 않았다.

장면 D 우선 후보는 **동국제강**(`서울 1425816 → KOTSA 04540-11291-00001-00-1`)이다. 시청에서 자산 좌표 기준 316.75m이고 서울 API의 이름·주소·13면·5분/700원이 [서울시설공단의 동국제강 안내](https://www.sisul.or.kr/open_content/parking/bbs/bbsMsgDetail.do?bcd=private_park&msg_seq=40)와 대응한다. 공단 안내는 과거 게시물이므로 현재 요금·운영 시간은 이번 응답과 현장으로 재확인한다. 이번 관측에서 갱신 시각이 계속 진전했다. API의 평일 운영은 09:00~19:00이므로 시연 시간도 고려해야 한다.

보조 후보는 **세종로**(`171721 → 03172-11291-00001-00-1`), 자산 좌표 기준 869.77m, 총 1,260면, 기본·추가 5분/430원, 평일 `0000~2400`이다. 500m 후보는 아니며 출입구 좌표 검증 후 1km 시연 후보로 쓴다. 관철동도 신선한 값은 있지만 주소가 다른 청계1(북)과 같은 주소로 내려오는 등 추가 확인 여지가 있어 우선순위를 낮춘다. 실측 값은 시연 당일의 빈자리를 보장하지 않는다.

## 6. 오류 응답 실측

세 경우 모두 **HTTP 200**이었다. JSON으로 요청해도 오류는 XML일 수 있다.

| 시험 | 범위·키 조건 | 본문 형식·코드 | 실제 MESSAGE |
|---|---|---|---|
| 키 오류 | 고정 가짜 키, 1/1 | XML `RESULT/CODE=INFO-100` | 인증키가 유효하지 않습니다. 인증키가 없는 경우, 열린 데이터 광장 홈페이지에서 인증키를 신청하십시오. |
| 범위 초과 | 정상 키, 1/1002 | XML `RESULT/CODE=ERROR-336` | 데이터요청은 한번에 최대 1000건을 넘을 수 없습니다. 요청종료위치에서 요청시작위치를 뺀 값이 1000을 넘지 않도록 수정하세요. |
| 데이터 없음 | 정상 키, 100000/100009 | JSON 최상위 `RESULT.CODE=INFO-200` | 해당하는 데이터가 없습니다. |

표본에는 원래 줄바꿈과 XML CDATA도 보존했다. 서버 오류·한도 초과·키 만료는 일부러 유발하지 않았고 일일·초당 허용량은 이 세 시험으로 판단할 수 없다. 요청 크기는 최대 1,000행으로 지키며 한도 경계의 구현을 넓게 추정하지 않는다.

## 7. 재실행과 검증

저장소 루트 PowerShell, Python 3.12와 Windows `curl.exe`, Python 표준 라이브러리만 사용한다. 아래 키를 명령행에 넣지 않는다. 환경변수를 설정하지 않으면 루트 `api`에서 읽는다.

```powershell
py -3.12 spikes/seoul-parking/probe.py --self-test
py -3.12 spikes/seoul-parking/analyze.py --self-test
py -3.12 spikes/seoul-parking/observe.py --samples 17 --interval 60 --prefix repeat-20261029
py -3.12 spikes/seoul-parking/analyze.py --index spikes/seoul-parking/out/repeat-20261029-index.json --output spikes/seoul-parking/out/repeat-summary.json
```

`--prefix`는 매번 새 이름을 쓴다. 도구는 기존 캡처를 덮어쓰지 않으며 실패한 관측에서 성공 자료처럼 진행하지 않는다. 현재 총계라면 17회/약 16분이며, 페이지가 늘면 전체 페이지를 매번 조회한다. 최초 실측은 접두사 옵션 추가 전에 실행되어 인덱스가 `out/observation-index.json`이다. 이 인덱스로 오프라인 분석을 재실행했다.

실행한 오류 시험(각 1회):

```powershell
py -3.12 spikes/seoul-parking/probe.py --label error-invalid-key --start 1 --end 1 --invalid-key
py -3.12 spikes/seoul-parking/probe.py --label error-range --start 1 --end 1002
py -3.12 spikes/seoul-parking/probe.py --label no-data --start 100000 --end 100009
```

경로/본문 키 제거, 정수형 실수, 미연계·오래된/미래 시각, 음수·초과·소수 차량 수, 0 총면수, 이름 구간 보존, 시청 거리 계산을 네트워크 없는 자체 검사로 확인했다. 앱 빌드·에뮬레이터·TTS는 실행하지 않았다.
